# Tunisian Tech Shopping Agent

A Python command-line assistant that turns a natural-language shopping request
into a ranked shortlist of laptops, desktop PCs, or phones from **Tunisianet**,
**Mytek**, and **Spacenet**, with prices in Tunisian dinars (TND).

> I need a laptop for programming under 2500 TND with at least 16 GB RAM.

Google Gemini extracts the shopping requirements and decides whether another
store should be searched. Python code retrieves listings, checks requirements,
and ranks the candidates. LangGraph connects these steps into a conditional
workflow.

## Features

- Extracts category, budget, intended use, brand preferences, and hardware needs.
- Asks for clarification when the request lacks enough detail to start searching.
- Searches stores in order: Tunisianet, Mytek, then Spacenet. It can stop early
  when Gemini considers the available selection sufficient.
- Returns up to six distinct options with prices, store links, and scores.
- Labels requirement gaps and details that could not be verified from listings.
- Prints a trace of the search and decision steps, including store failures.

## Getting started

You need **Python 3.11 or newer**, a **Gemini API key**, and internet access for
live searches. Download or clone this repository, open a terminal in its root
folder, and follow the steps for your platform.

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r shopping_agent/requirements.txt
Copy-Item .env.example .env
```

Edit `.env` and set `GEMINI_API_KEY` to your own key, then run:

```powershell
.\.venv\Scripts\python.exe -m shopping_agent
```

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r shopping_agent/requirements.txt
cp .env.example .env
```

Edit `.env` and set `GEMINI_API_KEY` to your own key, then run:

```bash
.venv/bin/python -m shopping_agent
```

The commands above use the virtual environment directly; activation is optional.
Use the same interpreter for the examples and tests below, or activate the
environment first so that `python` points to it.

## Usage

At the prompt, describe the product, your maximum budget in TND, and any
requirements. For example:

```text
What are you looking for? A laptop for programming under 2500 TND with 16 GB RAM
```

Other example requests:

- "An Android phone under 1200 TND with a good camera."
- "A desktop PC for video editing under 4000 TND."
- "An Asus gaming laptop with a dedicated GPU under 5000 TND."

The result includes a top recommendation and any alternatives, with a score out
of 100, match status, store, price, and product link. If a requested specification
is missing from a listing, the result asks you to verify it before buying. If no
products are found, it reports that instead.

### Python API

From the repository root, with the dependencies installed:

```python
from shopping_agent.main import run_agent

state = run_agent("A laptop for programming under 2500 TND with 16 GB RAM")
recommendation = state["final_recommendation"]
products = state["products"]
```

`run_agent` returns the final graph state and also prints progress and results.
Vague requests can prompt for terminal input, including when called from Python.

## How it works

```text
Shopping request
      |
Parse intent (Gemini) <--- Ask for clarification
      |                           ^
      +---- Missing details ------+
      |
Search the next store (HTTP + HTML parsing)
      |
Evaluate candidates (Gemini when needed)
      |                           |
      | Need more candidates      | Enough candidates / no stores remain
      +---- Back to search        v
                           Compare and rank (Python)
                                  |
                           Print recommendations
```

Ranking uses explicit rules for requirement gaps, missing information, RAM,
storage, CPU/GPU families, phone families, and price relative to the maximum
budget. The final response is formatted in Python rather than generated by Gemini.

## Configuration

Copy [`.env.example`](.env.example) to `.env` in the project root. Existing process
environment variables take precedence over values in `.env`.

- `GEMINI_API_KEY`: required for live use; leave the committed example blank.
- `GEMINI_MODEL`: model name; defaults to `gemini-2.5-flash`.
- `SHOPPING_MAX_PAGES_PER_STORE`: listing-page limit; defaults to `3`, bounded to
  `1-10`.
- `SHOPPING_MAX_PRODUCTS_PER_STORE`: accepted-product limit per store; defaults to
  `24`, bounded to `1-100`.
- `SHOPPING_HTTP_CONNECT_TIMEOUT`: connection timeout in seconds; defaults to `4`.
- `SHOPPING_HTTP_READ_TIMEOUT`: read timeout in seconds; defaults to `8`.
- `SHOPPING_HTTP_RETRIES`: HTTP retry count; defaults to `1`, bounded to `0-4`.

Timeouts should be positive numbers. Invalid numeric settings fall back to their
defaults; integer settings outside their allowed ranges are clamped. Restart the
program after changing configuration.

Your shopping request and candidate listing details are sent to Gemini for
parsing and evaluation. Store pages are retrieved directly over HTTP. Keep your
API key in `.env` or the process environment; `.gitignore` excludes local `.env`
files while allowing `.env.example`.

## Tests

After installing the application dependencies, run:

```bash
python -m unittest discover -s tests -v
```

The suite uses Python's built-in `unittest` framework and mocks external calls.
It needs no Gemini API key and makes no requests to Gemini or the stores. GitHub
Actions runs these tests on Python 3.11 and 3.13 for pushes and pull requests.

## Troubleshooting

- **Missing API key:** set `GEMINI_API_KEY` in the root `.env` or process environment.
- **Gemini request or rate-limit error:** check the key, configured model, and API
  quota. For rate limits, wait before trying again.
- **A store fails or returns no products:** check your connection and the reported
  store URL. The store may block requests or have changed its HTML selectors.
- **Module import errors:** install the dependencies using the same interpreter
  you use to run the app, and run from the repository root.

## Limitations

- This is a CLI prototype. It provides shopping comparisons; purchases happen on
  the retailer's site.
- Searches cover a limited set of listing pages, may stop early, and do not
  guarantee the cheapest offer across all stores.
- Specifications are extracted from listing text, without fetching detailed
  product pages. Missing fields remain unverified.
- Scores use hardware and phone-family heuristics rather than benchmark results
  or measured camera quality. Store ratings and reviews are not currently collected.
- The maximum budget is enforced; the extracted minimum budget is not currently
  used for filtering. Operating-system checks cover only selected platforms.
- Store layout changes can break scraping. URLs and selectors are maintained in
  `shopping_agent/tools/stores.py`.
- Prices can change, and stock availability is not explicitly verified. Check
  the product page and final price before buying.
- Passing offline tests does not verify live store access or Gemini behavior.
